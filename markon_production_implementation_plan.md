# Implementation Plan: Markon Production Readiness & Automated JSON Rendering Polish

## 1. Objective

Bring `@nofinite/markon` to 100% production readiness for NPM publishing (`npm publish`), and resolve the 4 identified visual and styling deficiencies in `renderMarkon` / `MarkonRender` so that TipTap AST JSON generated by `MarkonEditor` renders automatically, cleanly, and beautifully across all modern web environments (including Tailwind / UnoCSS reset preflights and standalone Vanilla JS contexts).

---

## 2. Current Behavior & Identified Problems

### A. Publishing & Subpath Export Deficiencies (`package.json`)

1. **Missing Package Metadata:** `packages/markon/package.json` lacks `"author"`, `"homepage"`, and `"bugs"` fields, which are present in other production packages in `@nofinite/stack` (e.g., `@nofinite/media`).
2. **Subpath Export Inflexibility:** Downstream projects and bundlers that attempt to import `@nofinite/markon/dist/markon.css` or direct distribution files fail under strict Node/bundler ESM subpath resolution because `exports` only maps `./styles.css`.

### B. Renderer Aesthetic Deficiencies (`packages/markon/src/core/renderer.ts`)

1. **Unstyled List Markers in CSS Reset Environments:**
   - In Tailwind, UnoCSS, or Normalize preflight environments, default browser bullets (`list-style: disc`) and numbering (`list-style: decimal`) are stripped on `<ul>` and `<ol>`.
   - `MARKON_RENDERER_CSS` does not explicitly declare `.markon-content ul` or `.markon-content ol` styles, causing lists to lose their bullet/decimal markers.
2. **Monochromatic Code Syntax Highlighting:**
   - Code blocks run `lowlight` during rendering, producing AST tokens with classes like `.hljs-keyword`, `.hljs-string`, `.hljs-title`, `.hljs-comment`, etc.
   - `MARKON_RENDERER_CSS` has zero color definitions for `.hljs-*`. As a result, code blocks render with a background container but flat monochrome text.
3. **Misaligned KaTeX Math Formulas:**
   - Math blocks output HTML via `katex.renderToString()`.
   - Without baseline KaTeX CSS font metrics, horizontal fraction bars (`.katex .frac-line`), radical surds (`.katex .sqrt`), and centering rules, math expressions render misaligned on standalone pages.
4. **Standalone Callout / Alert Theme Fallbacks:**
   - Callout blocks render as `<div class="markon-callout alert alert-${type}">`.
   - In environments without global `@nofinite/nuicss` stylesheets loaded, the variant types (`info`, `warning`, `danger`, `success`, `tip`) lack self-contained OKLCH accent border and background tint fallbacks.

## 3. Proposed Solution

### Phase 1: Self-Contained Styles in `MARKON_RENDERER_CSS` (`packages/markon/src/core/renderer.ts`)

- **Reset-Proof Lists:**
  - Add explicit `list-style-type: disc`, `list-style-type: decimal`, padding (`padding-left: 1.5rem`), margin, and nested list indentation.
  - Support task lists (`ul[data-type="taskList"]`, `li[data-type="taskItem"]`, checkboxes).
- **Native OKLCH Syntax Highlighting:**
  - Embed clean, high-contrast OKLCH syntax token styles for `.hljs-keyword`, `.hljs-built_in`, `.hljs-type`, `.hljs-literal`, `.hljs-number`, `.hljs-operator`, `.hljs-string`, `.hljs-comment`, `.hljs-title`, `.hljs-function`, `.hljs-attr`, `.hljs-attribute`, `.hljs-punctuation`.
  - Harmonize colors for light mode and dark mode (`[data-theme="dark"]` and `@media (prefers-color-scheme: dark)`).
- **Self-Contained Alert/Callout Themes:**
  - Add scoped fallback styles for `.markon-callout.alert-info`, `.alert-success`, `.alert-warning`, `.alert-danger`, `.alert-tip` with semantic OKLCH borders and backgrounds.
- **Baseline KaTeX Math Alignment:**
  - Add minimal baseline CSS for `.katex-display`, `.katex .vlist-t`, `.katex .frac-line` to ensure formulas display cleanly even when standalone.

## 5. Alternatives Considered

- **Externalizing Highlight.js CSS theme:** Would require consumers to find and import an external stylesheet (e.g. `highlight.js/styles/github.css`). By embedding OKLCH token variables directly in `MARKON_RENDERER_CSS`, `@nofinite/markon` remains zero-config and matches the NUICSS palette seamlessly.
- **Forcing KaTeX CDN link injection:** CDN links can trigger Content Security Policy (CSP) errors in enterprise apps. Embedding baseline alignment rules into `MARKON_RENDERER_CSS` while keeping full KaTeX fonts optional allows graceful degradation.

---

## 6. Risks & Mitigations

- **CSS Specificity Clashes:** Ensure all renderer styles are strictly scoped under `.markon-render` and `.markon-content` to avoid leaking styles into host application pages.
- **Bundle Bloat:** The CSS additions are pure CSS strings (< 2.5 KB unminified), adding negligible overhead to the bundle.
